## 5. 미션 2-3 수정 기록

### 수정 1 — 정확한 정답도 오답으로 판정되는 문제

- **테스트 내용:** 이미지 등록 후 등록된 정확한 정답을 입력하여 제출.
- **예상 결과:** 입력한 이름과 저장된 정답이 일치할 때 정답 표시.
- **실제 결과(v1):** 정확한 정답을 입력했는데 오답으로 표시됨. 오류가 모든 이미지에서 발생하는지는 별도로 확인하지 못함.
- **AI에게 전달한 요청:** 정답 비교 로직을 검토하고 공백·대소문자 및 유니코드 표현 차이를 정규화하도록 수정하여 전체 HTML을 새 버전으로 제공하도록 요청.
- **수정한 부분:** 입력값과 정답을 비교하는 `normalize()` 함수를 수정함. NFKC 정규화, 공백/일부 비가시 문자 제거, 대소문자 통일 후 비교하도록 변경함. 직접 확인하지 않은 근본 원인을 확정하지 않음.
- **버전:** `캐릭터퀴즈_v2.html` (기존 v1 보존).
- **수정 후 테스트 결과:** **PASS (사용자 관찰)**. 이미지 등록 후 정확한 정답을 입력했을 때 정답으로 판정됨.
- **수정 이유:** 맞힌 문제도 오답 처리되면 정답 수가 왜곡되고 게임 결과를 신뢰하기 어려워짐.

### 수정 2 — 정답 이름 수정 시 목록 재생성 방지 (v3 재검증 완료)

- **문제 발견 경위:** v2 소스 검토 결과, 등록된 이미지의 정답을 편집하고 입력값을 확정하면 `commit()`에서 전체 이미지 목록을 다시 생성하도록 작성되어 있었음. 입력란을 포함한 목록의 DOM 요소가 교체된다는 점은 코드에서 확인했으나, 실제 사용자가 겪은 불편은 아직 관찰하지 못함.
- **테스트 내용·예상 결과:** 관리 화면에서 여러 정답을 수정하면서 Tab으로 이동 시 입력 흐름이 유지되는지 확인. v2 코드에서는 저장 시 전체 목록 DOM을 다시 만드는 동작이 확인되었으나, v2에서 실제 포커스 문제가 발생했다는 사용자 관찰은 없었음.
- **AI에게 전달한 요청:** 정답 수정 시 전체 이미지 목록을 재생성하지 말고, 저장 처리와 게임 시작 가능 여부/안내 문구만 갱신하도록 HTML 전체를 별도 v3 파일로 수정한다. 이미지 등록·삭제 시에는 기존처럼 목록을 갱신한다.
- **수정 내용:** `commit(candidate, refreshGallery)` 분기와 `updateStatus()` 함수를 두어 정답 이름만 변경할 때는 전체 갤러리를 다시 만들지 않음.
- **수정 이유:** 매번 목록을 재생성하면 입력 중인 요소가 교체되어 키보드 탐색이나 연속 입력에 불편이 발생할 가능성이 있음.
- **수정 후 테스트 결과:** **PASS (사용자 관찰)**. 정답 연속 수정, 수정 내용 저장, 빈 정답 시작 제한, 기존 기능 재검증 4항목 모두 PASS로 보고됨. 특이사항 없음. 단, v2의 실제 사용자 불편 발생 여부는 확인되지 않았으므로 예방적 개선으로 구분함.

### 수정 3 — 퀴즈 결과 화면 시각적 개선 (v4 재검증 완료)

- **발견한 문제(테스트 내용):** 친구 1명에게 캐릭터 이미지 10장 등록·정답 확인/수정·퀴즈 진행·결과 확인 작업을 요청함. 게임 완료 시 정답 개수가 나오는 결과 화면에 대해 '너무 심심함'이라는 관찰이 전달됨.
- **예상 결과:** 결과 화면에서 최종 맞힌 개수가 명확하게 보이면서 완료 화면으로서 시각적 구분이 충분할 것.
- **실제 결과(v3):** 점수는 표시되지만 결과 화면이 단조롭다는 관찰이 있었음.
- **AI에게 전달한 요청:** 기존 정답 수/전체 문제 수 및 기능을 유지하면서 결과 화면에 장식 요소와 점수 시각적 강조를 적용하고 새 전체 HTML을 v4로 보존하도록 요청.
- **수정 내용:** 결과 화면에 트로피 아이콘, 그라데이션 배경의 강조 패널, '퀴즈 완료! 맞힌 문제 수' 안내 및 큰 점수 글씨를 추가. 퀴즈 판정 및 데이터 저장 로직은 유지함.
- **수정 이유:** 완료 화면이 지나치게 단조로우면 사용자가 게임이 끝난 순간을 알아차리거나 성취감을 느끼기 어려울 수 있음.
