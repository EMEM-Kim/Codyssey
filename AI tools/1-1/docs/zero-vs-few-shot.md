# Zero-shot vs Few-shot 실제 응답 비교

## 실행 조건
- 사용자 수행: ChatGPT 새 채팅 A(Zero-shot), 새 채팅 B(Few-shot)에서 각각 1회 실행 후 응답을 현재 대화에 제출
- 모델: 사용자에게 동일한 GPT-6 모델·설정을 사용하도록 안내함. 개별 실행 환경을 독립 검증하지는 못함.
- 동일 PR: Python 3.12, Django 5, DRF의 UserProfileView
- 동일 요구사항: 로그인 사용자만 본인 프로필 조회/수정, 닉네임 2~20자
- 차이: Few-shot 조건에서 인증·인가 누락, 수량 범위 검증, 코드 없는 요청에 대한 예시 3개 추가
- 실행 코드/테스트: 없음. LLM 응답에 대한 정적 평가.

## 실제 결과의 핵심 비교
| 항목 | Zero-shot | Few-shot |
|---|---|---|
| 인증 누락 (AllowAny) | Critical | Critical |
| 소유권 검증 누락 (IDOR) | Critical | Critical |
| 닉네임 길이 검증 누락 | High | High |
| DoesNotExist 처리 누락 | Medium | Medium |
| nickname/username 혼용 | **Medium 독립 문제** | 추가 확인 사항에서 언급 |
| 최종 의견 | Request Changes | Request Changes |
| 발견된 문제 수 (독립 항목) | 5 | 4 |

## 사용자 제출 응답에서 확인된 원문 인용
### Zero-shot
> 해당 PR은 **인증 및 객체 접근 권한 검증이 없어 다른 사용자의 프로필을 조회하거나 수정할 수 있는 심각한 보안 취약점**이 존재합니다.

> **문제 #5. 닉네임과 username 필드 혼용**

> **리뷰 범위:** 제공된 변경 코드와 요구사항에 대한 정적 분석만 수행했습니다. 실제 코드 실행, 테스트 및 GitHub PR 확인은 진행하지 않았습니다.

### Few-shot
> 해당 PR은 인증 및 사용자별 접근 권한 검증이 없어 다른 사용자의 프로필을 조회하거나 수정할 수 있는 보안 문제가 있습니다.

> **총 4개의 문제를 발견했으며, 수정 후 재검토가 필요합니다.**

> 현재 구현은 `nickname`을 Django 기본 `User.username` 필드에 저장합니다. `username`은 기본적으로 고유값 제약이 있으므로 닉네임 중복 허용 정책과 충돌할 가능성이 있습니다.

> **검토 범위:** 제공된 코드와 요구사항에 대한 정적 분석만 수행했습니다. 실제 API 실행, 테스트 및 데이터베이스 검증은 수행하지 않았습니다.

## 해석
- 두 조건 모두 핵심 보안 취약점 2건과 입력 검증·예외 처리 문제를 정확히 식별했다.
- Few-shot도 username 혼용 문제를 인지했으나 독립된 문제 항목으로 분류하지 않았다.
- Zero-shot이 1점 앞섰지만 단회 표본이므로 Few-shot의 일반적인 성능 열위를 입증하지 않는다.
- 양쪽 모두 출력된 Markdown 표가 깨져 보여 형식 점수를 4점으로 평가했다.

## 한계 및 증거 보존
- 실제 두 응답의 **전문은 원본 ChatGPT 대화에 보존되어 있다.** 이 문서에는 비교표와 원문 발췌만 수록했다.
- 독립된 채팅에서 실행했다는 점은 사용자에게 안내된 절차와 제출 결과에 근거한다. 별도 로그로 검증하지 않았다.
- 재현성을 높이려면 사용자 원문 응답 전문과 당시 모델 설정을 함께 저장해야 한다.
